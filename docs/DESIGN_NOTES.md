# Design Notes: Fog + Sonar + Noise

## 设计目标
在保留俯视角幸存者“短周期决策 + 高密度反馈”爽感的同时，避免只做伤害数值堆叠。核心设计轴切到：
- **视野/信息控制**：你并不总能看到战场全貌。
- **噪声代价**：获取输出与信息会提升风险，而风险会反向改变刷怪生态。

## 与 VS/Brotato 的关键差异
1. **信息是稀缺资源，不是常量背景**  
   默认迷雾让敌我信息不对称，玩家需要主动用声呐“购买”短时可见性。

2. **输出行为会改写难度曲线**  
   高频攻击、冲刺、技能抬升噪声，噪声直接影响刷怪倍率、精英/追猎者概率。

3. **每次操作都在做风险交易**  
   “打得更快”不再只有正收益，会更早进入暴露档位，触发更危险生态。

4. **构筑不只看DPS，还看信息效率与噪声预算**  
   - 静默构筑：低噪、慢热、稳定。
   - 声呐构筑：信息密度高，容错更高但常伴随噪声压力。
   - 高爆发构筑：短时间强势，但更容易召来追猎者与精英浪潮。

## 系统闭环（简化）
1. 玩家攻击/机动/技能 → 2. 噪声上升 → 3. 刷怪与追猎压力上升 → 4. 玩家需要更多声呐获取信息 → 5. 继续抬噪。

闭环核心不是“惩罚玩家”，而是让玩家主动管理节奏：
- 什么时候压噪回稳。
- 什么时候接受暴露换取推进效率。

## 可读性与演出策略
- 视觉层：Fog + Sonar 波纹 + 揭示轮廓，保证“信息变化”可被看见。
- UI 层：噪声条、档位文本、追猎预警、TelegraphBus 警报统一提示。
- 数值层：噪声阈值与倍率可配置且可热重载，便于快速平衡迭代。

## 迭代原则（M3 后续）
- 优先强化“信息-风险”反馈一致性，再扩内容量。
- 每新增内容（地图、敌人、契约）都必须回答：
  - 它如何影响信息获取？
  - 它如何改变噪声成本？
